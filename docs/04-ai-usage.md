# 04 AI 辅助说明：AI 做了什么、人做了什么、怎么验证

如实记录：本项目的代码、合成数据、测试和文档，主要由 AI 编程助手在一次对话中生成和迭代完成。

## 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| Claude Code（模型 Claude Opus 5.5），桌面应用 | 读题、选题、方案设计、编写全部源码/测试/数据/文档、运行测试与真实模型场景、根据运行结果修复问题、提交与推送 |
| DeepSeek `deepseek-flash`（DeepSeek-V4.1-Flash，API） | 作为**被测 Agent 的决策模型**运行场景，不参与写代码。按候选人要求，提交的结果只使用 Flash 模型 |
| DeepSeek `deepseek-chat`（API） | 仅在开发前三轮使用；候选人随后要求只用 Flash 模型，这三轮的记录作为历史证据保存在 `examples/runs/history/`，不作为提交结果 |

## 验证方式：AI 生成的内容如何被验证

AI 写的代码没有直接采信，而是通过下面几层验证：

1. **单元测试**：38 个 pytest 用例覆盖规则、时段、存储幂等、保存二次校验、finish 校验、循环上限、模型接入解析，以及全场景 Mock 回放。命令：`python -m pytest -q`。
2. **真实模型场景回放**：11 个场景，每个场景带机器可检查的期望（[examples/scenarios.json](../examples/scenarios.json)），输出 `checks.json`。开发期间用 deepseek-chat 跑了 3 轮（7/11 → 10/11 → 11/11）；提交结果用 deepseek-flash，跑了 1 轮完整回放和 3 次稳定性回放（结果见 [03-evaluation.md](03-evaluation.md)）。
3. **逐条阅读 trace**：检查模型给出的 `reason` 是否真的基于工具结果。正是通过阅读 trace 发现了“请求 note 泄露场景提示”的问题（见 05）。
4. **历史证据保留**：修复前的失败运行保存在 [examples/runs/history/](../examples/runs/history/)，没有被覆盖。

## AI 生成内容的已知风险

- 合成数据和规则词表是 AI 编写的，覆盖面有限，不代表真实的合规标准。
- 系统提示词中的业务策略（例如“替代时段默认不早于原要求”“争同一时段时优先调整有窗口的素材”）是 AI 根据题意提出的假设，需要业务方确认。
- 第 2 轮之后，在提示词里加了一条通用的冲突处理策略。这条规则没有提到具体素材，但它是在看到 09 场景失败之后加的，存在“针对测试调提示词”的风险。为此用重复回放来衡量稳定性，而不是只展示一次成功的运行。
